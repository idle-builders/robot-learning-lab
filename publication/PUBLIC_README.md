# Robot Learning Lab

A research workbench for learning control and perception for a roughly **50 cm ape-shaped robot**. The public repository contains reusable Python code, experiment definitions, firmware and electronics source, robot configurations, and the local results dashboards.

This is a learning POC. Saved motion and design observations are simulation evidence; physical operation, motor behavior and a complete build remain unqualified. Earlier 35 cm experiments and reference robots are historical evidence. The exact mechanical selection and its limitations are recorded in `robot/ape-current-design.json`.

## Start the empty dashboards

The dashboard uses Python's standard library. From the repository root:

```sh
PYTHONPATH=. python3 tools/results_hub.py serve
```

Open [Robot learning](http://127.0.0.1:8805/) for control and perception, or [Robot design](http://127.0.0.1:8805/design/) for CAD and electronics. The server binds to loopback. A fresh checkout creates its own empty local SQLite catalog and does not require cloud credentials.

For local secret checks before pushing, install Gitleaks and run `git config core.hooksPath .githooks`. GitHub Actions also checks the source boundary and scans public history.

Use `python3 tools/results_hub.py design-template --robot-section Knee` to inspect the design record format. To publish your own local evidence, write a result JSON record and run `PYTHONPATH=. python3 tools/results_hub.py publish /path/to/result.json`. The catalog records local assets and their hashes; `upload` is a separate, explicit command.

## Simulation and training

Core model generation uses Python 3.12 and the dependencies in `pyproject.toml`:

```sh
python3.12 -m venv .venv
.venv/bin/python -m pip install -e .
```

Training and optional hardware toolchains have separate `requirements-*.txt` and platform lock files. Start with `experiments/compact_morphology/mjlab_ape/` for low level control and `experiments/ape_high_level/` for perception. Reference integrations remain in `workers/`. GPU jobs use temporary compute; authored source and experiment records stay local.

This source release does **not** include pretrained policies, datasets, CAD exports, the private results catalog, raw sensor recordings, downloaded third-party reference trees, or the original lab history. Many historical scripts cite those inputs and cannot replay their runs from source alone. Provide the exact matching inputs and hashes before attempting native replay. A missing private asset is not evidence of a reproduced result.

## Source and private evidence

Read [the public/private boundary and publication workflow](docs/operations/public-upstream.md). Git holds authored source and reviewed configuration. Selected evidence is stored in a separately authorized private bucket, with full byte and SHA-256 verification before local eviction. Runtime databases, recovery manifests, credentials and signed URLs are private.

The archive is unconfigured in a fresh public checkout. Configure your own destination with `.env.example` or ignored `data/private-archive.json`; install `boto3` only when using cloud operations. Environment credentials or a local AWS profile supply authentication. The original lab's Keychain lookup is enabled only by its private local configuration. The old Runpod S3 transport is a separate historical integration with its own configuration and credentials; it is not the retained evidence archive.

The public repository starts with fresh history. It contains no original branches, tags, stashes or private recovery bundles. New publications use the exact inventory generated by `tools/public_source.py`; do not push the private lab's branches to the public remote.

There is no repository-wide open-source license selected for the authored material yet. Retain existing third-party notices; access to this source does not grant access to private evidence or change upstream licenses.
