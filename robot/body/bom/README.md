# Robot BOM and assembly order: start here for hardware

Everything needed to build the selected Cove-50 body starts from this folder: what to print and buy, from which
scripts and files, with which print setup, and in which order it goes together (owner 2026-11-20 / 2026-11-22, Idle
T-4jjry4, T-ghvncz). The selected body is `body_manifest` in [robot/design.json](../../design.json); nothing here is
hand-written output: every page below is regenerated by a script from the manifest and the data files in Git.

## Regenerate

```bash
.venv/bin/python -B robot/body/bom/build.py            # seconds; add --publish to update the design dashboard BOM
```

Outputs (derived, `.cache/work/bom/`): `BOM.md` (the builder's page), `ASSEMBLY.md` (build sequence per subassembly),
`bom.json`, `assembly.json`, `bom.csv`, `dashboard-bom.json`. After any change to the selected body (a builder rerun,
a new selection, a screw or part change), rerun the assembly check, then the BOM, then the BOM check:

```bash
python3 infra/tools/memguard.py --limit-gb 6 --timeout-s 1800 -- .venv/bin/python -B robot/body/checks/run.py --checks assembly --label assembly
.venv/bin/python -B robot/body/bom/build.py
python3 infra/tools/memguard.py --limit-gb 4 --timeout-s 900 -- .venv/bin/python -B robot/body/checks/run.py --checks bom --label bom
```

The same three commands are the last steps of the body chain ([chain.json](chain.json)), so a full rebuild
(`rebuild_chain.py setup && run && compare`, in an isolated copy under `.cache/work/body-rebuild/`) refreshes the BOM
of the rebuilt body too. `build.py` shows the assembly check's measurement per step when
`.cache/work/cad-speed/checks/assembly/report.json` is complete and on the same manifest.

## Files

| File | What | Who edits |
|---|---|---|
| `build.py` | generates the BOM and the build sequence | code |
| `lines.json` | grouping of parts into make / buy lines, supplier, part number, price, notes, manual lines (filament, glue, wire), per-part overrides; its values win over the generated ones | agents, by hand |
| `defects.json` | printed parts without a scripted native STEP (`groups`) and file references that resolve nowhere (`dangling`), with what fixing each takes and its Idle task | agents, by hand |
| `hardware.py` | every screw, nut, washer and spacer as a buyable spec, plus generated STEP / STL at its placement | code |
| `inventory.py` | per-part audit: where each file comes from, producer script, flags | code |
| `chain.json`, `rebuild_chain.py` | the ordered builder steps that recreate the selected manifest, then the assembly check, BOM and BOM check | data + code |
| [`../checks/data/assembly_order.json`](../checks/data/assembly_order.json) | the assembly order: subassemblies in build order, steps, directions | agents (seeded by `../checks/assembly_seed.py`) |

## Reading a BOM line (`bom.json` `lines[]`)

- `id`, `name`, `make_buy` (make / buy / included with a bought part), `quantity` (the CAD count unless `lines.json`
  overrides it; `quantity_cad` is always the CAD count), `sections`, `material`, `unit_mass_g`.
- `supplier`, `part_number`, `unit_cost`: only from a source in the repo (actuator catalog, electronics selection,
  standard designations); `unknown` where there is none. Prices are never guessed.
- `assembly`: the subassemblies and step ids where the line's parts go in (e.g. `right_leg p012, s013`).
- `parts[]`: each CAD part with its `step` / `mesh` and how they resolve (`step_status`, `mesh_status`), `producer`
  (the script that writes it) and `regenerate` (the command, from `chain.json`), `print` (printer, material, nozzle,
  layer, up direction, via `checks/process.py`), `generated_hardware` (the standard part's STEP / STL),
  `assembly_steps`, `flags` (mesh only, file missing, no print settings, no assembly step, ...).
- `spec` (hardware lines): kind, thread, length, head standard; `BOM.md` adds the driver from `checks/data/tools.json`.

## The assembly order

`assembly_order.json` lists the subassemblies in build order; each is built in place on what came before
(`after`): **torso** (stage-1 chassis with the hip yaw, shoulder pitch and neck yaw servos, battery, power and compute
electronics) -> **neck_head** -> **right_arm**, **left_arm** (with hands) -> **right_leg**, **left_leg** ->
**final_body** (torso shells). Within each: parts before the screws that fix them, covers last. A step is a part (a
printed part travels with its pressed steel sleeves), a set of screws, and `with` (nuts, washers, spacers, inserts and
parts without geometry that go in with it). `direction` is the manifest-frame vector the part travels as it goes in
(+X the R_ side, -Y the face, +Z up).

Step status: **designer** (ordered by the part's designer, e.g. the roll-flip hip steps), **confirmed** (the assembly
check measured the insertion path clear over 60 mm / the driver path free and not closed in later; the step says
which run), **seeded** (drafted from the connection graph, not yet supported). Seeded steps whose path is blocked are
the open work: either the order or direction is wrong, or the design needs a change (then an Idle task).

```bash
PYTHONPATH=robot/body .venv/bin/python -B robot/body/checks/assembly_seed.py seed [--names right_arm] [--search]   # add what is missing (memguard: ~1 min, 4 GB)
PYTHONPATH=robot/body .venv/bin/python -B robot/body/checks/assembly_seed.py confirm --report .cache/work/cad-speed/checks/assembly/report.json
```

`seed` keeps every existing step and inserts what no step names (parts by fastened distance from what is present,
screws right after the parts they join, hardware on its screw's step); a `plan.mirror_of` assembly starts as the
mirror of the other side. Edit steps by hand when the check or the designer says so; reseeding never drops them.

## Keeping it current (every agent)

- Start hardware work from `BOM.md` / `ASSEMBLY.md`, not from a manifest or an old study folder.
- When you add, remove or rename a part or screw: rerun `assembly_seed.py seed` (it places the new ones), check the
  new steps, rerun the assembly check, `build.py` and the bom check; fix `lines.json` if a new part needs a line,
  supplier or note.
- When a builder becomes part of the selected body, add its step to `chain.json` before the three BOM steps.
- Design findings (a part that cannot go in, a screw no driver reaches) go to an Idle task for the part's designer
  with the measurement; the order records the step as seeded until it is supported.
